Temporal and Explainable Machine Learning for Early Financial Fraud Detection

A leakage-free comparison of transaction-level, temporal and behavioral models. This page walks through the problem, the method, a working in-browser prototype, the verified benchmark results and the research plan.

01Problem and why it is hard

Problem statement. Develop and evaluate a leakage-free ML framework for financial fraud detection that compares transaction-level models with temporal and behavioral models, and explains individual fraud predictions.

Class imbalance

Only 0.172% of transactions are fraud. A model that says "legitimate" for everything scores 99.83% accuracy and catches zero fraud. We use PR-AUC, precision, recall and F1 instead.

Temporal behavior

Transactions arrive as a stream. Gap since the previous transaction, recent count and deviation from the card's normal amount carry signal that a single row does not.

Evaluation leakage

A random split trains on the future and tests on the past. A chronological split (train on early data, test on later) matches real deployment.

02Pipeline

Raw transactions→ Dataset audit + duplicate removal→ Chronological split 60/20/20→ Train-only preprocessing→ Static + temporal features→ LR / RF / XGBoost / LightGBM→ LSTM / GRU (where sequences valid)→ Threshold tuned on validation→ SHAP explanations→ Metrics, drift and ablation

Leakage rules followed

  • Scaler, feature selector and SMOTE are fit on training data only.
  • Decision threshold is chosen on validation data, never on test.
  • Temporal features use only transactions that happened before the current one.
  • The test period is evaluated once, after model selection is finished.

03Live prototype

This runs in your browser. It generates a 48-hour stream of 20,000 card transactions with injected fraud bursts and concept drift, builds leakage-safe temporal features, trains logistic regression on the earliest 60%, tunes the threshold on the next 20% and tests once on the final 20%. ULB has no card IDs, so true per-card sequences are built on IEEE-CIS rather than faked from row order.

Models compared

  • Logistic Regression — simple, interpretable linear baseline.
  • Random Forest — strong nonlinear tree ensemble.
  • XGBoost / LightGBM — gradient boosting, best for tabular data.
  • MLP — neural tabular baseline.
  • LSTM / GRU — read the last k transactions of a card as a sequence.

Imbalance strategies

  • Class weighting (used in the prototype)
  • SMOTE, applied inside the training fold only
  • Undersampling
  • Threshold tuning on validation data

Features

Static
  • V1–V28
  • Amount, log amount
  • Hour of day
Temporal
  • Time since previous transaction
  • Count in last 1 hour
  • Rolling mean / std of amount
  • Deviation from recent behavior
Behavioral (needs IDs)
  • Card-level average amount
  • Device / email / address change
  • Amount z-score vs history

08Limitations, ethics and future work

Limitations

  • ULB features are anonymized PCA components.
  • Only 2 days of data, so long-term drift is limited.
  • No customer IDs on ULB.
  • Benchmarks come from different pipelines.
  • SHAP shows attribution, not causality.

Ethics

  • False positives block real customers.
  • The model supports a human reviewer and does not decide alone.
  • Public anonymized data only.

Future work

  • Temporal graph neural networks
  • Transformer sequence models
  • Online learning for drift
  • Cost-sensitive learning
  • Federated, privacy-preserving training

09Viva quick answers

Why not use accuracy?

With 0.172% fraud, predicting "legit" for everything gives 99.83% accuracy and catches nothing. PR-AUC, recall and precision focus on the rare fraud class.

What is data leakage here?

Any information from validation/test or from the future reaching training: random splits that train on later transactions, fitting the scaler or SMOTE on all data, or choosing the threshold on the test set.

Why apply SMOTE only after splitting?

SMOTE makes synthetic frauds by interpolating between real ones. If done before the split, synthetic points built from test frauds leak into training and inflate results.

Why is PR-AUC better than ROC-AUC here?

ROC-AUC uses the false positive rate, whose denominator is the huge number of legitimate transactions, so many false alarms still look small. PR-AUC uses precision, which directly shows how many alerts are false.

Why not just use 0.5 as threshold?

Probabilities are skewed under imbalance and the right threshold depends on business cost (review capacity vs missed fraud). We tune it on validation data. The XGBoost benchmark selected 0.266.

What is SHAP?

SHapley Additive exPlanations: game-theory based attribution that splits a prediction into contributions from each feature. Global view: which features matter overall. Local view: why this one transaction was flagged.

Why LSTM/GRU, and why not on ULB?

They learn from ordered sequences such as the last k transactions of the same card. ULB has no card IDs, so valid sequences are built on IEEE-CIS. GRU is a lighter version of LSTM with fewer gates.

What is concept drift?

Fraud patterns and customer behavior change over time, so a model trained on old data degrades. We test it by evaluating early, middle and late windows separately. Try the drift slider in the prototype.

What is your contribution if temporal fraud detection already exists?

A controlled, reproducible comparison that measures how much temporal and behavioral information adds over strong baselines, under strict leakage-free chronological evaluation, with explainability and false-positive constraints.
